## What

Le badge OS natif (#223) n'a toujours pas de correction **premier plan** : la route `badge: 0` n'a aucun trigger serveur (jamais de rappel sur foyer vide, crossings jamais vers 0) — l'utilisateur vide sa liste sur /to-buy, le badge OS reste collé à N jusqu'à la fin des temps (rien côté page ne touchait au badge : `setAppBadge|clearAppBadge` = SW + son test uniquement).

## Fix : resync foreground à cycles exacts

Principe : **jamais de count approximatif** dans le badge (il écraserait un count correct livré par un push). Tous les writes au badge partent des **raw rows DB** des fetches complets (vérité instant exacte — `getLowStockItems(joinInventory(...))` sur les items non filtrés, déjà calculée à `page.tsx:72`).

- **`src/hooks/useAppBadgeSync.ts` (nouveau)** — `useAppBadgeSync(count: number | null)` : contrat #223 verbatim
  - `null` → no-op (pas de données ≠ jamais clear) ; `> 0` → `setAppBadge` ; `0` → `clearAppBadge` (rejections swallowées) ;
  - API absente (Firefox desktop) → no-op silencieux ; guards `!Number.isInteger || count < 0` identiques au SW ;
  - **jamais de reset au unmount** (le badge OS garde la dernière vérité jusqu'au prochain update/push — même raison que #223).
- **`src/app/to-buy/page.tsx`** (surface low-stock, url push `/to-buy`) :
  - état `lowStockCount` (init `null`) alimenté à CHAQUE `fetchItems` — zéro compute ajouté (réutilise la ligne existante) ;
  - cycles : **mount** + **reconnect** (`useResyncOnReconnect` existant) + **fallback patch-error** (`onResyncNeeded` existant) + **`visibilitychange` hidden→visible** (refetch silencieux ; `requestId` guard déjà en place, dédup gratuit).

## Non-goals (documentés dans l'issue #247)

- Entre cycles, les patches realtime corrigent la liste mais **pas le badge** (pas de delta : LWW-skips + écritures optimistes casseraient l'exactitude) — corrigé au prochain cycle ; le badge affiche donc **jamais un count faux**, au pire transitoirement paresseux.
- Trigger serveur pour `badge: 0` : décision séparée — aucun touch sur `enqueue_daily_reminders` / `notify-thresholds`.
- Routage toast par canal : régi par #224, hors scope.
